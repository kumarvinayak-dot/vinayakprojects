Step 1

Start the comparison tool (launch_comparison_tool.bat or start_server.bat) and open http://localhost:5000/crm.

Step 2

Check the Build Comparison checkbox on the home page.

Step 3

Select CRM/AMSS only (do not select ASCF, UXF/OMNI, or DEX).

Step 4

Enter the previous CRM SDK path in Old build and the new CRM SDK path in New build.

Use UNC paths to the SDK JAR or folder for both builds.

Step 5

In JAR names for manifest diff (comma-separated), enter JAR names or patterns (e.g. AmdocsSecurityManager.jar, scala*.jar) to verify MANIFEST.MF Implementation-Version between old and new builds.

Step 6

In JAR names for class diff (comma-separated), enter JAR names (e.g. ClfyBillingManager.jar, ClfyCore.jar) to compare decompiled Java/class changes in the report.

Step 7

Leave Full content comparison as the default CRM mode (automatic when only CRM/AMSS is selected).

Step 8

Click Run comparison and wait for the HTML report to open (enable pop-ups if blocked).

Large SDK comparisons may take 30+ minutes depending on network and disk speed.

Step 9

In the report, review the JAR manifest diff (optional) — summary table for old vs new Implementation-Version per JAR and path.

Check primary paths and ClfyAgent bundle paths when the JAR appears inside nested archives.

Step 10

In the report, review the JAR class file diff (optional) — summary section and Perforce-style Java source differences for the JARs you listed.

Use Open in the summary table to jump to each JAR’s decompiled diff.

Step 11

Confirm manifest versions and class changes match expected build verification results before sign-off.

Save the HTML report from \\YOUR-PC\c$\crm_compare_reports if audit is required.
