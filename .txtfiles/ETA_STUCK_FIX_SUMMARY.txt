HOW IT WORKS NOW:
-----------------

1. STARTUP:
   - comparison_start_time is set when comparison begins
   - total_files is calculated from archive count
   - processed_files starts at 0

2. DURING COMPARISON:
   - For each file/archive processed:
     * processed_files increments
     * current_file updates to current filename
     * _update_progress() is called
     * Progress percentage = (processed_files / total_files) * 100
     * ETA = avg_time_per_file * remaining_files

3. PROGRESS BAR SHOWS:
   - Percentage complete (e.g., "45.3%")
   - Files processed (e.g., "453 / 1000")
   - Current file being compared
   - Estimated time remaining (e.g., "2m 15s")

WHAT IF COMPARISON IS SLOW:
---------------------------
If your lightsaber.zip comparison is taking a long time:

1. Check the progress bar - you'll see exactly where it is
2. ETA will tell you how much longer (e.g., "15m 30s")
3. Current file shows which specific archive is being processed
4. If it's stuck on one file for >10 minutes, per-file timeout will trigger

Network paths can be slow - consider using --use-local-copy:
  py main.py --custom-folders --archives --use-local-copy ^
    --folder1 "\\RAAISILON\..." ^
    --folder2 "\\RAAISILON\..."

This copies files to local temp folder first (much faster).

TROUBLESHOOTING:

   timeout will trigger automatically.

A: Progress is logged every 10 files. Check console output while comparison runs.
