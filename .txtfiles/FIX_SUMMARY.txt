PROBLEM STATEMENT:
------------------
When comparing SDK JAR files between HFB22 and HFB21 releases:
  Folder 1: SDK_CRM_10.0.1.22_linux64_20251120_2043.jar (HFB22)
  Folder 2: SDK_CRM_10.0.1.21_linux64_20250908_1434.jar (HFB21)

The comparison report showed "No differences found" but there were 
version-specific naming convention differences in nested paths:
  - winpack__V10_0_1_22.jar vs winpack__V10_0_1_21.jar
  - Unsigned JAR naming differences
  - AmdocsCRM.ear version suffixes

These naming differences were causing confusion because they were 
EXPECTED differences between releases (not actual content changes).

================================================================================

SOLUTION IMPLEMENTED:
---------------------
Enhanced the archive filename normalization in src/folder_compare.py
to handle CRM-specific naming patterns:

1. CRM Version Patterns (__V10_0_1_22):
   - winpack__V10_0_1_22.jar  → winpack.jar
   - winpack__V10_0_1_21.jar  → winpack.jar
   - Result: Both normalize to same name = NO FALSE POSITIVE

2. Embedded Versions (_10.0.1.22_):
   - SDK_CRM_10.0.1.22_linux64_20251120_2043.jar → SDK_CRM_linux64.jar
   - SDK_CRM_10.0.1.21_linux64_20250908_1434.jar → SDK_CRM_linux64.jar
   - Result: Both normalize to same name = NO FALSE POSITIVE

3. Unsigned JAR Suffixes:
   - module_unsigned.jar → module.jar
   - module.jar          → module.jar
   - Result: Both normalize to same name = NO FALSE POSITIVE

4. AmdocsCRM.ear Versions:
   - AmdocsCRM_10.0.1.22.ear → AmdocsCRM.ear
   - AmdocsCRM_10.0.1.21.ear → AmdocsCRM.ear

TECHNICAL DETAILS:
------------------
The normalization uses these regex patterns (applied in order):

1. Remove "unsigned" suffix:
   r'[-_]unsigned$'

2. Strip CRM version patterns:
   r'__+V\d+(?:[_\.]\d+)*'

3. Strip embedded versions:
   r'_\d+\.\d+(?:\.\d+)*(?:\.\d+)*_'

4. Strip standard version suffixes:
   r'[-_]\d+\.\d+(?:\.\d+)*(?:-[A-Za-z0-9]+)*$'

5. Strip timestamps:
   r'[-_](?:b?\d{3,}|build-?\d+|\d{8}(?:_\d{4})?|\d{14})$'

6. Clean up extra underscores/dashes

The normalization is applied recursively to all nested archives,
ensuring consistent comparison at all levels.
