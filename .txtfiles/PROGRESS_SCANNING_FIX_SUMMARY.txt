ISSUE:
------
When comparing lightsaber.zip files directly:
  \\RAAISILON\...\BN212\lightsaber.zip
  \\RAAISILON\...\BN210\lightsaber.zip

Progress bar showed:
  Status: Running
  Files processed: 0 / 1
  Estimated time remaining: Calculating...

And stayed stuck there even though the comparison was actually working.

ROOT CAUSE:
-----------
When comparing two archive files directly (file-to-file), the code set:
  total_files = 1  (because comparing 1 pair of archives)
  processed_files = 0

But the REAL work happens in these hidden phases:
1. Scanning archive 1 (reading thousands of files inside)
2. Scanning archive 2 (reading thousands of files inside)
3. Comparing the contents

These phases could take minutes/hours for large archives like lightsaber.zip,
but there was NO progress shown during scanning. The progress bar stayed at
"0 / 1" until the entire comparison finished.

Result: User thinks it's stuck when it's actually working hard!

FIX APPLIED:
------------
Changed archive comparison to show DETAILED PROGRESS with 3 phases:

PHASE 1: Scanning Archive 1
  - Shows "Phase 1/3: Scanning lightsaber.zip..."
  - Updates every 100 entries: "Scanning lightsaber.zip: 1000/5000 entries"
  - Shows nested archive processing: "Processing nested archive: path/to/file.jar"

PHASE 2: Scanning Archive 2
  - Shows "Phase 2/3: Scanning lightsaber.zip..."
  - Updates every 100 entries with progress
  - Shows total files found after scan

PHASE 3: Comparing Contents
  - Shows "Phase 3/3: Comparing archives..."
  - Updates every 100 files: "Comparing 1000/5000 common files"
  - Shows completion message

TIPS FOR FASTER COMPARISON:
----------------------------

1. Use --use-local-copy for network paths:
   py main.py --custom-folders --archives --use-local-copy ^
     --folder1 "\\RAAISILON\..." ^
     --folder2 "\\RAAISILON\..."
   
   This copies to local temp first (much faster scanning).

2. Skip deep nested scanning if not needed:
   Set deep_nested_archives = False in ArchiveContentsComparer
   (This scans only top-level files, not nested JARs)

3. Use web UI to see real-time progress:
   py builtin_server.py --host 0.0.0.0 --port 5000
   Open http://localhost:5000
   Watch the progress bar update in real-time!

TROUBLESHOOTING:
----------------

Q: Progress still shows "Calculating..." for ETA?
A: Normal for Phase 1. ETA will appear after Phase 1 completes
   (need at least one phase done to estimate).

Q: "Scanning" phase takes very long?
A: Large archives with deep nesting are slow. Progress updates every 100
   entries show it's working. Consider --use-local-copy for network paths.

Q: Stuck on "Processing nested archive: ..."?
A: Large nested JAR is being scanned. This can take minutes for big JARs.
   Progress will resume after nested archive completes.

Q: Want to skip nested scanning?
A: Not exposed in UI yet. For now, nested scanning is always enabled for
   thorough comparison. Future: Add --shallow-scan option.
